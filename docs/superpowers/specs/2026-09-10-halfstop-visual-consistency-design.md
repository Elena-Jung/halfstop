# 화면을 하나로 묶기: 치수 토큰과 앱 셸

2026-09-10. 사용자와 함께 "왜 완성도가 부족해 보이는가"를 진단해 나온 설계입니다.
`2026-09-09-halfstop-ui-design.md` 의 화면 구조 절을 잇습니다.

## 왜 바꾸는가

사용자가 배포된 화면을 보고 말했습니다.

> 지금 웹사이트가 왜 완성도가 부족해보인다는 감이 들까

감이 아니라 숫자로 재 봤습니다. 1280×900, 사진 세 장을 불러온 상태입니다.

| 기둥 | 높이 | 끝나는 y |
|---|---|---|
| 미리보기 | 570px | 776 |
| 설정 칸 | 419px | 625 |
| 레일 | 176px | 382 |
| 화면 | 900px | |

세 기둥이 나란히 서는데 높이가 전부 다릅니다. 레일의 세로선은 176px 에서 끊기고, 그 아래
설정 칸 옆이 비고, 그 아래 화면이 124px 빕니다. `.app` 이 1100px 로 잠겨 있어 1280 화면에서
좌우 90px 씩, 1920 화면이면 410px 씩 빕니다. 사진이 없는 첫 화면은 아래 218px 이 빕니다.

`src/assets/ui.css` 968줄의 값을 세어 봤습니다.

| 항목 | 상태 |
|---|---|
| 간격 | `2 / 4 / 6 / 8 / 10 / 12 / 14 / 16 / 24` 가 규칙 없이 섞임 |
| 모서리 반경 | `0 / 2 / 4 / 6 / 8 / 12 / 50%` 일곱 가지 |
| 글자 크기 | 사실상 `12` 와 `13` 둘. 제목 `20`, 오버레이 `18` 하나씩 |
| 전환 효과 | 없음 |

**원인은 하나입니다.** 여섯 개의 작업이 각자 CSS 를 썼고 공유하는 체계가 없었습니다. 색만
토큰이고 치수는 작업자마다 눈대중이었습니다. 그 결과가 두 증상으로 보입니다. **조각들이 따로
놓임**(같은 화면인데 한 벌로 안 보임)과 **화면이 비어 보임**(기둥 높이가 제각각, 바깥 여백이
큼)입니다.

사용자가 이 둘을 골랐고, 전환 효과 없음과 글자 위계 없음은 고르지 않았습니다. 이번 설계는
고른 둘만 다룹니다.

## 무엇으로 바꾸는가

세 덩어리를 이 순서로 합니다.

1. **치수 토큰**을 세우고 그 밖의 값을 거부하는 검사와 지침 문서를 만듭니다. 지금 CSS 를
   토큰에 맞춥니다.
2. 그 토큰으로 **앱 셸**을 짓습니다. 화면 높이를 다 쓰고 세 기둥이 선으로 만나는 편집기
   모양입니다.
3. 기계 검사와 눈 확인으로 **검증**합니다.

**순서가 중요합니다.** 지침이 먼저 있어야 셸 작업을 맡을 작업자가 같은 흔들림을 또 만들지
않습니다. 셸을 먼저 지으면 새 값을 또 뿌리고 나중에 그것까지 옮겨야 합니다.

## 1. 치수 토큰

`ui.css` 의 `:root` 에 세 묶음을 더합니다. 테마와 무관한 값이므로 `[data-theme='light']`
에는 넣지 않습니다. `theme.test.ts` 는 6자리 16진수만 뽑으므로 이 토큰이 같은 블록에 있어도
무시합니다.

```css
/* 간격. 4px 배수이고 숫자는 4의 배수 개수입니다. */
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-6: 24px;

/* 모서리 */
--radius-sm: 4px;
--radius-md: 8px;
--radius-lg: 12px;

/* 글자 */
--text-sm: 12px;
--text-md: 13px;
--text-lg: 20px;
```

**지금 값을 여기에 맞춥니다.** 어긋난 값이 24곳이고 규칙은 셋입니다.

| 지금 | 어디 | 바꿈 |
|---|---|---|
| `6px` 세로 안쪽 여백 | 목록 트리거, 목록 옵션, 글자칸, 파일 고르기 | `--space-2`(8px) |
| `10px`, `14px` 가로 안쪽 여백 | 카드, 트리거, 글자칸, 파일 고르기 | `--space-3`(12px). 조작 요소 안쪽 여백은 전부 `8 / 12` 하나로 통일 |
| `6px`, `10px` 사이 간격 | 카드 사이, 썸네일 사이 | `--space-2`(8px). 같은 묶음 안 항목 사이입니다 |
| `10px` 사이 간격 | 불러오기 줄의 단추와 썸네일 묶음 사이, 색 창의 구역 사이 | `--space-3`(12px). 묶음과 묶음 사이입니다 |
| `2px` 아래 여백 | 썸네일 줄 | `--space-1`(4px) |
| 모서리 `2px` | 슬라이더 트랙 | `--radius-sm` |
| 모서리 `6px` | 목록 옵션 | `--radius-sm`. **안쪽 모서리는 바깥 모서리 한 단계 아래**입니다. 8px 목록 안의 옵션이 같은 8px 이면 모서리가 겹쳐 보입니다 |
| 모서리 `6px` | 전체 선택 단추, 색 창 닫기 단추 | `--radius-md`. 단추는 md 입니다 |
| 글자 `18px` | 드롭 오버레이 | `--text-lg` |

`0`, `auto`, `50%`(둥근 손잡이), `-1px`(sr-only 의 `margin`)은 그대로 씁니다. 테두리
두께(`1px`, `1.5px`, `2px`, `3px`)와 `outline-offset`, 위치 값(`top`, `left`)은 치수 규칙
밖입니다.

**세로 여백 6→8 은 눈에 거의 안 보입니다.** 트리거, 글자칸, 단추는 `min-height: 32px` 이
이미 받치고 있어 1px 차이입니다. 눈에 띄는 것은 카드와 펼친 목록 항목이 4px 높아지는 것과
목록 안쪽 모서리가 6→4 로 줄어 바깥 8 과 겹쳐 보이지 않게 되는 것입니다. 사용자가 1:1
시안을 보고 8/12 를 골랐습니다.

## 2. 검사 `src/ui/scale.test.ts`

`theme.test.ts` 와 같은 방식입니다. `ui.css` 를 `node:fs` 로 읽어 두 가지를 봅니다.

**토큰이 위 표와 정확히 같은지.** 이름과 값을 모두 비교합니다. 단계를 몰래 더하거나 값을
바꾸면 여기서 걸립니다. 단계를 바꾸려면 검사를 같이 고쳐야 하고, 그것이 의도입니다.

**토큰 블록 밖의 선언이 토큰만 쓰는지.** `:root` 와 `[data-theme='light']` 블록과 주석을
걷어낸 뒤 `padding`, `padding-*`, `margin`, `margin-*`, `gap`, `row-gap`, `column-gap`,
`border-radius`, `font-size` 선언을 전부 찾아 값을 공백으로 나눕니다. 각 조각은 아래 중
하나여야 합니다.

| 속성 | 허용 |
|---|---|
| 간격 계열 | `0`, `auto`, `-1px`, `var(--space-N)` |
| `border-radius` | `0`, `50%`, `var(--radius-*)` |
| `font-size` | `var(--text-*)` |

`font-size: var(--space-3)` 처럼 계열이 틀리면 실패합니다. `calc()` 는 허용하지 않습니다.
필요해지면 검사를 고치는 것이 맞습니다. 실패 메시지에 줄 번호와 선택자를 넣습니다.

TSX 의 인라인 `style` 은 검사하지 않습니다. 색 견본의 배경색과 색 판 손잡이의 위치처럼 실행
중에 계산되는 값이 거기 있고, 그것은 정당합니다. 지침이 인라인 style 을 그 용도로만 제한합니다.

## 3. 지침 `docs/css-style.md`

`AGENTS.md` 처럼 규칙마다 이유를 답니다. **새로 정하는 것은 1번과 2번뿐이고 나머지는 이미
저장소에 흩어져 있는 관행을 한곳에 모으는 것입니다.**

- 색은 토큰만. 새 토큰은 두 테마 모두에 정의하고 `theme.test.ts` 에 짝을 더합니다.
- 치수는 토큰만. `scale.test.ts` 가 검사합니다. 어느 단계를 어디에 쓰는지 표를 둡니다.
  조작 요소 안쪽 `2 / 3`, 같은 묶음 안 항목 사이 `2`, 묶음과 묶음 사이 `3`, 구역 안쪽 `4`.
  **쓰는 자리가 없는 단계는 선언하지 않습니다.** 필요해질 때 표와 검사를 함께 고칩니다.
- 안쪽 모서리는 바깥 모서리 한 단계 아래.
- 조작 요소는 `min-height: 32px`, 아이콘만 있는 단추는 44px.
- 상태는 `data-*` 속성으로 전달. `:checked` 와 `:has()` 로 상태를 읽지 않습니다.
- 감추기는 sr-only. `display: none` 과 `visibility: hidden` 은 초점을 잃습니다. `[hidden]` 에
  `display` 를 준 요소는 `[hidden] { display: none }` 을 따로 써야 합니다.
- `outline: none` 금지. 전역 `:focus-visible` 을 물려받습니다.
- 구분선은 `border` 가 아니라 `box-shadow` 로 그려 선택 표시용 `border-color` 와 겹치지 않게
  합니다. 레일이 그 예입니다.
- 인라인 `style` 은 실행 중 계산되는 값만.
- 브라우저별 가상 요소(`::-webkit-*`, `::-moz-*`)는 한 선택자 목록에 묶지 않습니다.
- 눈으로 확인할 것: 두 테마, 767px 아래, 키보드 초점, 설정 칸 스크롤.

`AGENTS.md` 의 `<documents>` 표와 `<conventions>` 에 연결합니다. 지금 브리프마다 "반드시
지킬 것"으로 여섯 줄씩 반복되는 목록이 이 문서 한 줄을 가리키는 것으로 바뀝니다.

## 4. 앱 셸

시안 셋을 그려 보고 사용자가 **편집기 크롬**을 골랐습니다. 둘러싼 부분은 한 단계 밝은 면
(`--surface`) 위에 올리고, 사진이 놓이는 바닥만 가장 어둡게(`--bg`) 둡니다. 면과 면은 1px
`--border` 선으로 만나고 선끼리 모서리에서 이어집니다. 사진 편집기가 대체로 이 모양입니다.

기각한 둘. **선 격자**는 면 차이 없이 선만으로 가르는데, 사진 바닥과 조작면이 같은 색이라
묶임이 약했습니다. **떠 있는 패널**은 지금 언어에 높이만 맞춘 것인데, 패널 사이 틈이 "조각들이
따로 놓임"을 그대로 남깁니다.

### 격자

`.app` 이 `height: 100dvh` 의 세 줄 격자가 됩니다. `grid-template-rows: auto auto minmax(0, 1fr)`.
폭 제한 1100px 과 바깥 여백 24px 을 없앱니다. `body` 의 `margin: 0` 은 이미 있습니다.

| 줄 | 내용 | 면 | 선 | 여백 |
|---|---|---|---|---|
| 헤더 | 제목(`--text-lg`), 테마 단추(44px) | `--surface` | 아래 1px | `--space-2 --space-4` |
| 불러오기 줄 | `[사진 고르기] [전체 해제] 썸네일… 장수 · 상태 문구` 한 줄 | `--surface` | 아래 1px | `--space-2 --space-4` |
| 본체 | 세 기둥, `gap: 0` | | | |

**불러오기 줄은 항상 이 모양입니다.** `data-compact` 분기와 큰 점선 `.intake`, `.hint` 가
없어집니다. 사진이 없을 때는 `[사진 고르기]` 만 있고, 전체 해제와 장수는 사진이 있을 때만
붙습니다. 썸네일 묶음은 지금처럼 한 줄 가로 스크롤입니다. `role="status"` 인 상태 문구는 줄
오른쪽 끝에 `--text-sm`, `--text-dim` 으로 두고, 비어 있으면 자리를 차지하지 않습니다.

### 본체 세 기둥

`grid-template-columns: minmax(0, 1fr) 280px auto`. 지금 레일과 설정 사이 16px 틈이 사라지고
선 하나로 만납니다.

**미리보기** `--bg`, `display: grid; place-items: center; padding: var(--space-4); min-height: 0`.
캔버스는 `max-width: 100%; max-height: 100%; width: auto; height: auto` 만 둡니다. 지금의
`width: 100%`, `min-height: 200px`, `background: var(--surface)` 는 뺍니다. 캔버스는 대체
요소라 두 제한을 함께 받아도 고유 비율을 지킵니다. 미리보기 백킹은 이미 긴 변 1600 고정
(`PREVIEW_LONG_EDGE`)이고 CSS 가 줄이는 구조라 `src/core/` 와 `usePipeline` 은 건드리지
않습니다.

**설정** 280px, `--surface`, 왼쪽 1px, `padding: var(--space-4)`, `overflow-y: auto;
min-height: 0`. 프리셋 카드는 지금 모양(테두리, 둥근 사각형, 왼쪽 표시자) 그대로입니다.
사용자가 정한 시각 언어입니다.

**레일** `--surface`, 왼쪽 1px, `padding: var(--space-2) var(--space-1)`. 기둥 높이를 다
씁니다. 탭 사이 `box-shadow` 구분선은 그대로입니다.

### 사진이 없을 때

시안 셋 중 사용자가 **미리보기 자리가 통째로 놓는 곳**을 골랐습니다. 미리보기 칸에
`2px dashed var(--border)`, `--radius-lg` 의 점선 상자가 칸을 다 채우고, 안내 두 줄이 가운데
옵니다. 첫 줄 `사진을 끌어다 놓거나 여기를 눌러 고르십시오`, 둘째 줄은 형식과 상한과
"사진은 브라우저를 떠나지 않습니다" 입니다. 문구는 사전에 키로 둡니다.

이 상자는 파일 입력을 가리키는 `label` 입니다. 누르면 고르기가 열리고, 새 상태나 이벤트가
필요 없습니다. 한 입력에 `label` 이 둘(불러오기 줄의 단추와 이 상자)인 것은 유효한 HTML 이며
입력에 `id` 만 있으면 됩니다. 창 전체 드롭과 `.hs-drop-overlay` 는 그대로입니다.

기각한 둘. **한 동작만 남김**(위 줄을 감추고 강조색 단추 하나)은 첫 화면이 가장 단순하지만
사진을 넣는 순간 위 줄이 나타나 미리보기가 72px 내려앉습니다. **지금 방식**은 화면에서 가장
큰 자리가 빈 채로 시작합니다.

### 서체 목록 잘림

설정 칸이 스크롤 컨테이너가 되면 `position: absolute` 인 `.hs-listbox-list` 가 칸
가장자리에서 잘립니다. 스크롤 컨테이너는 절대 위치 자손을 자르고, 그것을 피할 CSS 는
없습니다.

`Listbox` 가 목록을 `createPortal` 로 `document.body` 에 띄우고, 트리거의
`getBoundingClientRect()` 로 `position: fixed` 의 `top`, `left`, `width` 를 인라인 style 에
넣습니다. 실행 중 계산값이라 지침이 허용하는 인라인 자리입니다. 위아래 뒤집기 계산은 이미
`window.innerHeight` 기준이라 그대로 맞습니다. 설정 칸이 스크롤되거나(캡처 단계의 `scroll`)
창 크기가 바뀌면 닫습니다. 바깥 클릭 판정에 목록 ref 를 넣어야 포털 밖이라고 닫히지
않습니다. `aria-controls` 와 `aria-activedescendant` 는 id 기반이라 포털을 넘어도 됩니다.

색 고르기 창은 이미 `position: fixed` 백드롭이라 무관합니다.

### 좁은 화면

767px 아래도 `height: 100dvh` 를 유지하고, 본체만 세 칸에서 세 줄로 바꿉니다.
`grid-template-rows: minmax(0, 45dvh) minmax(0, 1fr) auto` 이고 미리보기, 설정,
레일(가로, 위 1px) 순입니다. 설정 칸의 `overflow-y: auto` 는 넓은 화면과 똑같이 둡니다.

**`position: sticky` 로 미리보기를 붙이는 방법은 쓰지 않습니다.** 그리드 항목의 컨테이닝
블록은 자기 그리드 칸이라 칸 안에서만 움직일 수 있고, 칸 높이가 곧 내용 높이면 움직일 여지가
없어 아무 일도 일어나지 않습니다. 위처럼 줄 높이를 직접 정하면 미리보기가 늘 화면 위쪽
45dvh 를 차지하고 그 아래만 스크롤합니다. UI 스펙의 "두 배치 모두 사진이 계속 보입니다"가
아직 안 지켜지고 있었는데 이번에 채웁니다.

767/768 경계는 `Rail` 이 `useSyncExternalStore` 로 구독하는 매체 질의와 같아야
`aria-orientation` 이 실제 배치와 어긋나지 않습니다. 그대로 둡니다. CSS 는 지금처럼 기본이
좁은 화면이고 `@media (min-width: 768px)` 가 셸입니다.

### 없어지는 것

`.app` 의 `max-width`, `padding`, `margin`. `.intake` 의 점선 테두리와 `data-compact` 분기.
`.hint`. `.layout` 의 `gap: 16px`. `.preview-canvas` 의 `width: 100%`, `min-height`,
`background`. `.rail` 의 `padding-left: 12px`.

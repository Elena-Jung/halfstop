# halfstop UI 설계 (2단계)

- 작성일: 2026-09-09
- 상태: 승인 대기
- 앞선 문서: [halfstop 설계](2026-09-09-halfstop-design.md)
- 앞선 계획: [렌더 파이프라인](../plans/2026-09-09-halfstop-render-pipeline.md)

## 배경

1단계에서 렌더 파이프라인을 완성했습니다. JPEG 한 장을 넣으면 하단 정보 바가 붙은 이미지를
내려받을 수 있고, 미리보기와 내보내기가 같은 코드 경로를 쓰며, 전체 해상도 작업은 워커에서
돕니다. 테스트 166개가 붙어 있습니다.

다만 화면은 뼈대입니다. 옵션 이름이 `BAR_HEIGHT` 같은 내부 식별자 그대로 나오고, 색을
지정하지 않아 어두운 테마에서 대비가 부족하며, 프리셋이 하나뿐입니다.

이번 단계의 목적은 **이것을 실제로 쓸 만한 화면으로 만드는 것**입니다. 그리고 화면이 나와야
고칠 점이 나오므로, 브랜드 정규화나 HEIC 같은 것보다 먼저 합니다.

## 이번 범위

- 프리셋 아홉 개와 레이아웃 함수 둘
- 오른쪽 아이콘 레일과 설정 패널, 좁은 화면에서는 하단 탭
- 어두운 테마와 명암 대비
- 옵션에 사람이 읽는 이름과 묶음 붙이기
- 설정을 브라우저에 저장하기
- 브랜드 로고 번들과 브랜드 정규화
- 촬영 정보가 없는 사진에 대한 확인 창과 검토 화면
- i18n 틀과 한국어 사전
- WCAG 2.2 AA

### 이번 범위에서 뺀 것

- 여러 장 동시 처리와 ZIP 내려받기
- EXIF 수동 편집 패널
- HEIC 와 RAW 입력
- 영어 사전
- 배포와 컨테이너 검증

## 프리셋 아홉 개

선행 프로젝트 `exif-frame` 의 테마 16종을 참고해 후보를 그리고, 실제로 보면서 골랐습니다.
오버레이(사진 위에 글자를 얹는 방식)는 뺐습니다. **이 도구는 사진 둘레에 더하는 것이지 사진
위에 그리는 것이 아니기 때문입니다.** 사진에 글자를 얹는 일은 성격이 다르고 편집 도구가 할
일입니다.

### 하단 바 계열 여섯

| 프리셋 | 배치 | 내용 |
|---|---|---|
| 바디와 렌즈 | split | 왼쪽에 바디 제조사와 모델, 오른쪽에 렌즈 제조사와 모델, 아래 가운데에 노출값 |
| 장비와 노출 | split | 왼쪽에 바디와 렌즈, 오른쪽에 초점거리·조리개와 셔터·ISO |
| 한 줄 | single, 가운데 | 모든 값을 한 줄로. 바가 가장 낮아 사진을 가장 적게 깎습니다 |
| Shot on | single, 가운데 | 장비명을 크게 앞세우고 노출값을 작게 답니다 |
| 미니멀 | single, 왼쪽 | 장비명만 작게. 노출값을 빼고 사진을 방해하지 않습니다 |
| 필름 데이터백 | split | 검정 바탕에 주황 고정폭 글꼴. 필름 카메라가 날짜를 새기던 방식 |

필름 프리셋에 새 글꼴이 필요하지 않습니다. 1단계에서 JetBrains Mono 를 이미 번들했고 그것이
고정폭입니다. 서체 선택 옵션에서 고르면 됩니다.

### 액자 계열 셋

| 프리셋 | 여백 | 배치 |
|---|---|---|
| 폴라로이드 | 사방, 아래를 넓게 | split |
| 레터박스 | 좌우 0, 상하만, 배경 검정 | single, 가운데 |
| 포스터 | 사방 크게 | poster |

## 레이아웃 구조

아홉 개를 함수 아홉 개로 만들지 않습니다. **함수는 둘이고 프리셋은 그 위의 옵션 값
묶음입니다.**

```ts
interface Preset {
  id: string;
  labelKey: string;
  layout: 'bar' | 'matte';
  values: Record<string, OptionValue>;
}
```

이렇게 두면 프리셋을 늘릴 때 코드를 쓰지 않아도 되고, 사용자가 값을 바꿔 만든 변형을 그대로
저장할 수 있습니다. 프리셋과 사용자 변형이 같은 모양의 데이터가 됩니다.

### 텍스트 슬롯

두 함수 모두 **슬롯**에 글을 넣습니다. 슬롯은 셋입니다.

- `primary`: 주 줄과 부 줄
- `secondary`: 주 줄과 부 줄
- `footer`: 한 줄

각 줄은 템플릿 문자열입니다. 비면 그리지 않습니다. 템플릿에 토큰이 없으면 리터럴이 그대로
나오므로, 포스터의 제목처럼 사용자가 직접 쓴 글도 같은 방식으로 다룹니다. 새 기능이 필요
없습니다.

### `bar` 함수

1단계의 `src/core/layout/presets/infoBar.ts` 를 이 함수로 넓힙니다. 지금은 좌우 두 칸이
고정이고 슬롯도 배치 모드도 없습니다. 새로 만들지 않고 고쳐 씁니다. 기존 테스트가 좌우 배치를
검사하고 있으므로 `split` 모드의 회귀 테스트로 그대로 살립니다.

사진 아래에 띠를 붙입니다.

| 배치 모드 | 슬롯 쓰임 |
|---|---|
| `split` | `primary` 왼쪽, `secondary` 오른쪽, `footer` 아래 가운데 |
| `single` | `primary` 만, 정렬 옵션에 따라 왼쪽·가운데·오른쪽 |

옵션은 `MODE`, `ALIGN`, `PRIMARY_MAIN`, `PRIMARY_SUB`, `SECONDARY_MAIN`, `SECONDARY_SUB`,
`FOOTER`, 그리고 배경색·글자색·바 높이·여백·글꼴·크기·굵기·구분자입니다.

`ALIGN` 은 `single` 에서만 뜻이 있습니다. `split` 일 때는 설정 화면에서 **감춥니다.** 뜻이
없는 항목을 흐리게 남겨 두면 왜 못 만지는지 설명할 자리가 없고, 스크린 리더에는 그냥 사용할 수
없는 항목으로 읽힙니다.

### `matte` 함수

사진 사방에 여백을 두고 아래 여백 안에 글을 넣습니다. 여백은 **면마다 따로** 받습니다. 이
하나로 폴라로이드와 레터박스와 포스터가 모두 나옵니다.

| 배치 모드 | 슬롯 쓰임 |
|---|---|
| `split` | `primary` 왼쪽, `secondary` 오른쪽 |
| `single` | `primary` 만, 정렬에 따라 |
| `poster` | 세 줄 세로 쌓기. 위 작게, 가운데 크게, 아래 작게 |

`poster` 의 슬롯 대응은 다음과 같습니다.

| 화면 위치 | 슬롯 | 기본 내용 |
|---|---|---|
| 위, 작게 | `primary.main` | `{TAKEN_AT}` |
| 가운데, 크게 | `primary.sub` | 사용자가 직접 쓴 제목 (토큰 없는 리터럴) |
| 아래, 작게 | `secondary.main` | `{MAKER}{BODY}{MM}` |

가운데 줄의 크기 배율은 옵션으로 둡니다. `secondary.sub` 와 `footer` 는 `poster` 에서 쓰지
않습니다.

### 캔버스 크기

`matte` 는 사진보다 캔버스를 키웁니다. 1단계에서 이미 다룬 문제이며 `clampExportSize` 가
기기 한계 안으로 자릅니다. 다만 여백을 크게 준 포스터에서 이 한계에 더 일찍 닿으므로,
**줄어들었을 때 알리는 문구가 실제로 눈에 띄어야 합니다.**

## 옵션 스키마 확장

`PresetOption` 에 두 필드를 더합니다.

```ts
labelKey: string;   // 설정 화면에 보일 이름의 번역 키
groupKey: string;   // 어느 레일 칸에 들어갈지
```

**둘 다 번역된 문자열이 아니라 키입니다.** `core` 는 번역하지 않는다는 원칙을 지키고, UI 가
로케일에 맞춰 옮깁니다.

`groupKey` 가 레일 구성을 정합니다.

| 레일 칸 | 담기는 것 |
|---|---|
| 프리셋 | 프리셋 아홉 개 목록 |
| 프레임 | 배경색, 여백, 바 높이, 배치 모드 |
| 텍스트 | 서체, 크기, 굵기, 색, 정렬, 템플릿, 구분자 |
| 내보내기 | 해상도, 형식, 품질 |

프리셋이 하나뿐일 때 레일이 빈약해 보이는 문제는 아홉 개가 되면서 사라집니다.

## 화면 구조

### 넓은 화면

왼쪽에 미리보기 캔버스, 오른쪽에 설정 패널, 맨 오른쪽에 세로 아이콘 레일입니다.

### 좁은 화면

위에 미리보기, 그 아래 설정 패널, 맨 아래 가로 탭 바입니다. 레일이 아래로 내려와 가로가
됩니다.

**두 배치 모두 사진이 계속 보입니다.** 이 도구는 슬라이더를 조금씩 움직이며 결과를 보는
작업이라, 사진이 가려지면 만지는 뜻이 줄어듭니다. 좁은 화면에서 탭을 아래에 두는 것은 엄지가
닿는 자리이기 때문입니다.

보조 기술 쪽에서 보면 두 배치는 **같은 구조**입니다. `tablist` 의 `aria-orientation` 만
`vertical` 과 `horizontal` 로 바뀝니다.

### 아이콘

`lucide-react` 를 씁니다. ISC 라이선스이고 쓰는 아이콘만 번들에 들어갑니다.

**아이콘만 있는 단추에는 반드시 접근 가능한 이름을 붙입니다.** 이름 없는 아이콘 단추는 스크린
리더에게 `단추` 로만 읽힙니다.

### 어두운 테마

기본이 어두운 테마입니다. 편집 화면이 밝으면 주변 밝기가 사진 판단을 흐립니다. 사진 도구가
대체로 어두운 이유입니다.

색은 CSS 변수로 한 곳에 모읍니다. 명암 대비 검사는 어두운 배경에서 먼저 합니다.

## 접근성

목표는 WCAG 2.2 AA 입니다. 상세 항목은 [앞선 설계 문서](2026-09-09-halfstop-design.md)의
접근성 절에 있습니다. 이번 단계에서 실제로 해소할 것은 다음입니다.

| 지금 상태 | 할 일 |
|---|---|
| `<canvas>` 에 접근 가능한 이름이 없음 | `role="img"` 와 `aria-label`. **프레임에 그린 문자열과 같은 출처에서 만듭니다.** 따로 지으면 보이는 것과 읽어주는 것이 어긋납니다 |
| 상태 문구가 바뀌어도 알리지 않음 | `role="status"` 영역 |
| 옵션 이름이 내부 식별자 | `labelKey` 로 사람이 읽는 이름 |
| 색 지정이 없어 대비 부족 | 어두운 테마 색을 CSS 변수로 정의하고 대비를 계산으로 확인 |
| 레일이 없음 | `tablist`, `tab`, `tabpanel` 역할과 화살표 키 이동 |
| 확인 창이 없음 | `role="dialog"`, `aria-modal`, 포커스 가두기, Escape, 포커스 원위치 |

## 브랜드 로고

### 조달

Wikimedia Commons 에서 **`Public domain` 태그가 붙은 파일만** 가져옵니다. 다음 10개는 태그를
직접 확인했습니다.

Canon, Nikon, Sony, Fujifilm, Leica, Panasonic, Olympus, Pentax, Ricoh, Hasselblad

`simple-icons` 도 후보였으나 27개 브랜드 중 9개만 있고 하필 Canon 이 없어 주 출처로 삼지
않습니다. 겹치는 브랜드에서 모양이 더 나은 쪽을 골라 쓸 수는 있습니다.

파일마다 출처 URL 과 라이선스 태그를 저장소에 기록으로 남깁니다. 태그가 없거나 저작권이 살아
있는 것은 넣지 않고 워드마크로 둡니다.

### 상표

**저작권은 없지만 상표권은 남습니다.** 우리 용도는 이 사진이 어떤 장비로 찍혔는지를 밝히는
사실 표시이고, 이것이 상표를 쓰는 자리 가운데 가장 방어하기 좋은 쪽입니다. 다만 후원이나
제휴로 오인될 여지를 만들지 않아야 합니다.

그래서 쓰는 자리를 제한합니다.

> 브랜드 로고는 **사용자 사진의 프레임 안에서만** 그립니다. 소개 페이지, 파비콘, 홍보 이미지,
> **프리셋 목록의 미리보기 썸네일**에는 쓰지 않습니다.

마지막 항목이 실제로 화면 설계에 영향을 줍니다. 프리셋을 고르는 목록의 썸네일에는 로고 자리에
회색 사각형이나 일반적인 글자를 씁니다.

### 정규화

EXIF 의 `Make` 와 `Model` 은 지저분합니다. `NIKON CORPORATION` 과 `NIKON Z 6_2`,
`ILCE-7M4`, `SIGMA 35mm F1.4 DG HSM | A` 같은 것들입니다. 규칙을 코드가 아니라 데이터로
둡니다. 자세한 내용은 앞선 설계 문서의 브랜드 정규화 절에 있습니다.

정규화 규칙과 픽스처는 **Sony, Canon, Nikon 순으로** 먼저 맞춥니다. 실제로 확인할 사진이 이
세 브랜드에서 나옵니다.

`Path2D` 변환은 빌드 시점에 합니다. 워커 캔버스에는 `HTMLImageElement` 가 없어 SVG 를 그릴 수
없기 때문입니다. 경로로 두면 배율과 무관하게 선명하고, 채움색만 바꾸면 밝은 배경과 어두운
배경을 파일 하나로 처리합니다.

## 촬영 정보가 없는 사진

판정 기준과 묻는 방식은 [앞선 설계 문서](2026-09-09-halfstop-design.md)의 해당 절에
있습니다. 요약하면 `toFields` 의 결과가 비어 있으면 정보가 없는 것으로 보고, 단추 둘로
묻습니다.

> 촬영 정보가 없습니다. 그래도 넣겠습니까?
>
> `모두 넣기` `검토하기`

**이번 단계에서는 파일 한 장에 대해서만 동작합니다.** 여러 장 처리가 없기 때문입니다. 그래도
지금 만드는 이유는 두 가지입니다. 한 장으로도 뜻이 있고, 여기서 모달 접근성 패턴을 제대로
세워두면 여러 장으로 넓힐 때 훨씬 쌉니다.

검토 화면은 줄이 하나뿐이어도 같은 구조로 만듭니다. 읽어낸 촬영 정보를 보여주므로 한 장이어도
볼 값어치가 있습니다.

## i18n

번역 키 구조와 사전 모듈을 넣되 **한국어 사전만 채웁니다.** 구조가 서 있으면 영어는 나중에
사전 파일 하나를 더하는 일입니다.

라이브러리를 쓰지 않습니다. 키가 백 개 남짓이라 타입이 붙은 사전 하나면 충분하고, 키 오타를
컴파일 시점에 잡을 수 있습니다.

`core` 는 번역된 문자열을 반환하지 않습니다. 키와 구조화된 값만 반환하고 UI 가 옮깁니다.
1단계에서 만든 `src/ui/errorMessage.ts` 가 이미 그 자리를 맡고 있으므로, 그것을 사전 구조로
옮깁니다.

## 설정 저장

고른 프리셋 id 와 그 위에서 바꾼 값을 `localStorage` 에 둡니다. 1단계에서 만든
`mergeValues` 가 선언에 없는 키와 타입이 맞지 않는 값을 걸러냅니다. 지금 그 함수는 호출자가
없는데 여기서 생깁니다.

저장 실패는 조용히 넘깁니다. 사생활 보호 모드에서 `localStorage` 가 던지는데, 설정이 저장되지
않는 것이 도구를 못 쓸 이유는 아닙니다.

## 검증

**단위 테스트.** 두 레이아웃 함수가 배치 모드마다 슬롯을 제대로 쓰는지, 여백 옵션이 캔버스
크기에 반영되는지, 저장하고 다시 읽었을 때 같은 값이 나오는지, 낡은 값이 걸러지는지.
브랜드 정규화는 실제 EXIF 문자열 픽스처로 스냅샷 테스트를 붙입니다.

**계산으로 확인.** 어두운 테마의 색 조합이 4.5:1 을 넘는지 계산합니다. 눈으로 보는 대신
숫자로 확인합니다.

**사람이 확인.** 스크린 리더로 실제로 쓸 만한지는 켜서 써봐야 합니다. VoiceOver 로 파일을
넣고 프리셋을 고르고 내려받는 데까지 가봅니다. 키보드만으로 같은 경로를 갑니다. 그리고 실제
카메라 사진으로 아홉 프리셋을 모두 그려 봅니다.

## 남은 위험

- **로고를 모으는 일이 코드가 아닙니다.** 파일마다 Commons 에서 받아 라이선스를 확인하고
  `Path2D` 로 바꿔야 합니다. 브랜드 수만큼 반복되는 손일이라 예상보다 오래 걸릴 수 있습니다.
- **프리셋 아홉 개가 모두 좋아 보인다는 보장이 없습니다.** 목업으로 고른 것이라 실제 사진에
  올렸을 때 달라 보일 수 있습니다. 옵션 값 묶음이라 버리는 비용은 낮습니다.
- **포스터 프리셋은 사용자가 제목을 직접 써야 뜻이 있습니다.** 비워두면 빈 액자가 됩니다.
  기본값에 안내가 될 만한 글을 넣을지 정해야 합니다.
- 화면이 커지면서 1단계에서 미뤄둔 자잘한 항목들이 드러날 수 있습니다. 진행 기록의 후속
  항목 목록을 이번 작업에서 함께 봅니다.
